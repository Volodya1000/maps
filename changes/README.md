# Фрагменты изменений

Каждый PR добавляет `changes/<номер-PR-или-задачи>.<тип>.md` с описанием результата для пользователя. Типы: `feature`, `bugfix`, `refactor`, `doc`. Например: `changes/5.bugfix.md`. Один PR может содержать несколько типов. Фрагмент должен быть непустым, без заголовка и списка технических коммитов.

До создания PR можно использовать номер связанной задачи; после создания PR при необходимости переименовать фрагмент. Не редактируйте общий `CHANGELOG.md` в обычных PR. Наличие нового фрагмента относительно базовой ветки проверяется локально и в CI.

Подготовка релиза:

```sh
uv run --locked towncrier build --version 0.3.0 --draft
uv run --locked towncrier build --version 0.3.0 --yes
```

Первая команда показывает результат без изменений. Вторая добавляет записи в `CHANGELOG.md` и удаляет использованные фрагменты. Итоговый changelog и удаления включаются в отдельный release-коммит. Сначала сохраните рабочие изменения в Git.
