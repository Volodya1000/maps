# Контрольные результаты маршрутизации

Получены до производственных изменений на `main`:
`062786c12cf71e9ace9e0be5d029b5ceae09f925`, SDK 8.0.427, Release.
Первоначальное исполнение всех 374 тестов успешно; после записи эти 15 fixtures
отдельно проверены обычным read-only запуском `RoutingBaselineTests`.

Проверяются геометрия и порядок альтернатив, все метрики, мостовые точки,
дорожные контакты и газовые идентификаторы. Не включается случайный `Guid`.
Для координат допуск 1e-9 градуса (~0,1 мм по широте), для остальных нецелых
чисел 1e-6 соответствующих единиц. Идентификаторы и счётчики точны.

Два сценария намеренно сохраняют типизированный отказ: `unmapped-road` и
`length-limit`. Остальные должны возвращать альтернативы; изменение количества
или порядка не скрывается сравнением множеств.

Однократное воспроизведение записи допустимо только в checkout исходного SHA:

```sh
MAPS_ROUTING_RECORD_BASELINE="$PWD/tests/CableRoutePlanner.Tests/Fixtures/RoutingBaseline" \
  dotnet test CableRoutePlanner.Desktop.slnf -c Release --no-restore \
  --filter FullyQualifiedName~RoutingBaselineTests
```

Затем переменную необходимо убрать и выполнить тот же тест для проверки файла.
Не перезаписывайте fixtures новой реализацией, чтобы устранить несовпадение:
сначала установите причину изменения и проверьте его отдельной регрессией.
