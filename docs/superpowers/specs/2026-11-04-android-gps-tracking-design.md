# GPS-геолокация и обход маршрута — дизайн

## Намерение

Добавить в Android-версию CableRoutePlanner офлайн-определение положения,
направления телефона и отслеживание фактически пройденных участков выбранного
маршрута. Геометрия маршрутизации, A* и правила допустимости остаются без
изменений. Desktop сохраняет прежнее поведение и не показывает GPS-интерфейс.

## Цели

- Получать координаты через Android `LocationManager`, а направление — через
  `SensorManager`, с корректным жизненным циклом Activity.
- Запрашивать только coarse/fine location после явного включения функции.
- Показывать на карте отдельные GPS-слои: точку, точность и сектор направления;
  первое измерение не меняет камеру.
- Дать пользователю центрирование и следование камеры, отключаемое ручным
  жестом карты.
- Реализовать чистый, тестируемый `RouteProgressTracker`, который объединяет
  достоверные интервалы покрытия и не засчитывает скачки/пропуски повторно.
- Поддержать start/pause/resume/finish обхода и атомарное локальное сохранение
  настроек геолокации и сессии обхода.

## Не цели и анти-цели

- Не менять A*, `RouteAlternative`, геоданные, препятствия или геометрию
  рассчитанных маршрутов.
- Не добавлять Google/Fused Location SDK, интернет, фоновой foreground service
  или разрешение фоновой геолокации.
- Не считать GPS-маркер пользовательской точкой и не включать его в
  `PlanningSession`.
- Не выдавать приблизительное/устаревшее/сомнительное положение за точное и не
  переносить прогресс на другую геометрию.

## Выбранный подход

Реализуется согласованный слоистый вариант:

1. Application содержит платформенные контракты, модели измерений/состояний,
   идентификацию геометрии и чистый `RouteProgressTracker`.
2. Android содержит адаптеры `LocationManager` и `SensorManager`, запросы
   runtime permissions, проверку системной геолокации и lifecycle-переходы.
3. ViewModels содержат отдельный `TrackingViewModel` и состояние местоположения
   без ссылок на Android/Avalonia. `MapViewModel` только связывает выбранный
   маршрут с tracking-состоянием.
4. UI/Mapsui получает отдельный адаптерный API для GPS, прогресса и камеры.
   Слои располагаются поверх маршрутов и пользовательских точек; обновление
   положения меняет features существующих слоёв.
5. Persistence использует отдельные JSON-файлы для location preferences и
   tracking session с записью через временный файл и замену.

## Контракты и данные

В Application будут добавлены:

- `LocationMeasurement` (координата, точность, UTC-время, скорость/признак
  приблизительности при наличии);
- `HeadingMeasurement` и состояние доступности направления;
- `ILocationService`, `IHeadingService`, `ILocationPreferencesStore` и
  `ITrackingSessionStore` с no-op реализациями для Desktop;
- `RouteProgressTracker` с конфигурацией порогов качества;
- snapshot сессии, fingerprint маршрута, объединённые интервалы и геометрия
  подсветки.

Fingerprint строится из порядка и точных координат `RouteAlternative.Geometry`.
Сохранённая сессия содержит также снимок geometry, чтобы восстановление могло
проверить соответствие, а не полагалось только на `Guid`.

## Прогресс

Трекер предварительно строит кумулятивную длину polyline. Каждое измерение
проверяется по времени, возрасту, точности и допустимой скорости; затем выбирает
совместимую проекцию на сегмент с учётом локального окна предыдущей проекции.
Интервал между двумя последовательными достоверными измерениями принимается
только при непрерывном времени/скорости и без скачка через большой пробел.
Интервалы нормализуются, пересечения объединяются, а длина считается по union.
При неоднозначных параллельных/пересекающихся участках выбирается кандидат,
совместимый с предыдущим route-position и направлением, а не просто ближайший
к экранной точке. После паузы, потери сигнала или смены маршрута continuity
сбрасывается.

## UX и lifecycle

- В настройках заголовок становится «Настройки»; секция «Местоположение» видна
  только при поддержке платформы и содержит один переключатель.
- Разрешение запрашивается только после включения. Отказ, approximate, отзыв,
  выключенный provider, отсутствие сигнала и выход за offline coverage имеют
  отдельные понятные состояния.
- GPS появляется автоматически при включённой настройке, но camera-follow не
  включается автоматически.
- Отдельная кнопка карты центрирует на известной точке и включает follow;
  ручной pan/rotate/zoom выключает follow, повторное нажатие включает его снова.
- Нижняя панель получает компактный блок обхода с общей длиной, пройденным
  unique coverage, остатком, процентом и состоянием.
- При смене альтернативы/точек/пересчёте старый прогресс не переносится:
  активная сессия приостанавливается и остаётся доступной для завершения или
  сохранения. После restart восстановление требует явного продолжения.
- При `OnPause` прекращаются обновления датчиков/фиксация новых интервалов;
  `OnResume` возобновляет их только если настройка включена.

## Тестирование и проверка

Сначала будут добавлены unit-тесты трекера и heading-математики, затем
ViewModel/persistence tests с fake-сервисами, Mapsui/Avalonia headless tests и
Android manifest/compile checks. Существующие routing tests не изменяются.
Локальная сборка/тесты будут запущены при наличии .NET SDK; при его отсутствии
это будет явно отмечено как `NOT VERIFIED`. Физические датчики и эмулятор не
будут заявлены проверенными без фактического запуска.

## Оставшиеся решения реализации

Пороговые значения качества (точность, возраст, скорость, разрыв между
измерениями) будут единым публичным объектом конфигурации трекера и покрыты
граничными тестами. Формат JSON остаётся внутренним и версионируется полями
сессии; существующий файл routing settings не меняется.
