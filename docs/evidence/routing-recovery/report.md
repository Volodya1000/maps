# Разбор 56 отказов и восстановление реальных маршрутов

Исходная версия — `171103262709792e360f84c7de665d40a1c17ec3` (PR #64). Неизменённый корпус содержит 88 пар: 32 успешные и 56 `NoRouteInSearchArea`. Его SHA-256 — `025262ab54548df41a43b71d230d003151b6e03b2541fec72a9b963e45e0634d`. Правила пересечения автомобильных дорог не меняются.

## Что установлено для всех 56 случаев

[Полный поимённый разбор](investigation.json) содержит исходные области поиска, доступные переходы, независимые попытки, ограничения и статусы всех 56 пар. Найдены четыре полных допустимых пути внутри прежней области и ещё три вне неё. Для остальных 49 независимая проверка не нашла доказанного обхода; это не доказательство физической непроходимости.

Прямая A–B не использовалась как доказательство отсутствия обхода. Исследовательский поиск строил консервативное свободное пространство, триангуляцию и связный путь, после чего весь путь проходил отдельный аудит исходных препятствий и правил. Проверены исходные области, запас 3 км и ограниченные попытки 5 км для компонентов, достигавших границы. Ограничения числа объектов, вершин и времени записаны отдельно; ограниченная попытка не становится отрицательным физическим заключением.

## Почему железная дорога и подземные переходы не изменили прежние 32/88

Историческое измерение 32/88 сделано до импорта железных дорог. Железнодорожные линии тогда игнорировались и уже не блокировали поиск. Их последующий нейтральный импорт добавил отображение и статистику, сохранив прежнюю возможность пересечения. Из 56 отказов только 22 загружают железнодорожные объекты, а прямые A–B пересекают их в пяти случаях.

У 55 из 56 отказов в прежней области нет кандидатов подземного перехода. Единственный случай — `mass-brest-bridge-01`: сеть из трёх линий связана с дорогами `way/693233769` и `way/701408716`, а целевая дорога пары — `way/100016850`. Включение флага увеличивает число порталов 10 → 13, но прежний поиск не достигает добавленной сети. Проверены все 88 входов с единственным изменением флага; исходные статусы не менялись. Контрольные сценарии Минска отдельно подтверждают работу разрешения там, где есть связная сеть.

## Что исправлено

Допустимая обычная геометрия внутри загруженной области возвращается прежним способом; выходы за её границу при мостовом выравнивании исправлены на всех этапах. После исчерпания поиска запускается более мелкая сетка в прежнем лимите узлов и резервный граф свободного пространства. Для подтверждённых внешних обходов область может увеличиваться вдвое и вчетверо, с прежним верхним запасом 5 км и обрезкой по пакету.

Резервная геометрия предлагает кандидатов; каждое ребро и окончательная трасса проходят прежнюю полную проверку evaluator/Domain. Поверхностный граф не превращает подземную линию в разрешение войти в неё произвольно. Ограничения источников и графа отражаются в диагностике, отмена передаётся между этапами. Мостовой splice ограничен реально загруженной областью: длинная исходная линия моста не разрешает уход в незагруженные препятствия.

Для сложного объединения буферов используется существующий NG overlay NTS без изменения точности координат. Сравнение на одинаковом расширенном Naliboki-02 выявило дорогой legacy overlay; новый способ проверяется отдельно и на полном наборе. Таймаут обвязки больше не теряет результат из-за различия `bytes`/`str` на разных ОС.

Полный локальный gate также выявил повторные дорогие проверки соединителей на отрицательном сценарии Минска: под coverage тест занимал 31 секунду и нарушал штатный предел неактивности 30 секунд. Геометрические факты соединителя теперь переиспользуются между стоимостными профилями в пределах одного расчёта; цена по-прежнему вычисляется для каждого профиля отдельно. Кеш ограничен исходным числом узлов и не переносится между запросами. Таймауты и дорожные разрешения не менялись.

## Автоматическая приёмка и воспроизведение

[Каталог свидетелей](witnesses.json) связывает геометрии с исходными сценариями, PBF и сжатыми извлечениями. Быстрые xUnit-тесты используют семь небольших полных фрагментов источника с настоящими границами покрытия, исходными WKB всех типов и прежними настройками. Они запускаются обычным `tools/check.py desktop` без загрузки полной карты.

В полном workflow сохраняются неизменённые 88 входов и шесть отдельных контролей. Семь доказанных случаев теперь имеют положительное ожидание у новой версии; старые отказы baseline сохраняются для честного сравнения. `routing_recovery.py` заново проверяет свидетелей и сырые результаты на полной карте, происхождение данных и реальные границы попыток. Последовательные попытки имеют один `CalculationId` и отдельные номера.

```powershell
uv run --project tools/GeodataPreparation --locked python tools/routing_regression.py --data artifacts/belarus --verify-dll tools/CableRoutePlanner.Verify/bin/Release/net8.0/CableRoutePlanner.Verify.dll --output artifacts/routing-regression
uv run --project tools/GeodataPreparation --locked python tools/routing_recovery.py --data artifacts/belarus --run-report artifacts/routing-regression/results.json --output artifacts/routing-regression/recovery
uv run --project tools/GeodataPreparation --locked python docs/evidence/routing-recovery/independent_probe.py --data artifacts/belarus --run-report artifacts/routing-regression/results.json --output artifacts/independent-probe --margin mesh --width 0.2
```

Последняя команда — ограниченный исследовательский инструмент для оставшихся отказов; его `unresolved` и `limited` не означают невозможность маршрута. Артефакт полного CI содержит фактические проценты, переходы статусов, сырые данные и контрольные суммы финального коммита. Локальная фикстура и успешный CI не заменяют проверку на физическом телефоне.
