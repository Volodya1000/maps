# Windows 7: выбор с минимальным дублированием

Дата исследования: 2026-10-23. Рекомендация для отдельного прототипа: **сохранить Avalonia 11 и общие XAML/ViewModels, добавить небольшой Desktop.Legacy host на .NET Framework 4.8**. Переход к отдельному WPF-интерфейсу сейчас означал бы поддержку второго набора экранов, жестов, стилей и UI-тестов. Поддержка Windows 7 в текущей net8-сборке не реализована этим решением.

## Основания

- Microsoft указывает Windows 7 SP1 среди ОС, на которые устанавливается [.NET Framework 4.8](https://learn.microsoft.com/dotnet/framework/get-started/system-requirements). Это совместимость runtime, а не продление жизненного цикла Windows 7.
- [Документация именно Avalonia 11](https://v11.docs.avaloniaui.net/docs/overview/supported-platforms/) описывает запуск на Windows 7 с ограниченной поддержкой. Пакеты [Avalonia.Desktop 11.3.0](https://www.nuget.org/packages/Avalonia.Desktop/11.3.0), [Mapsui.Avalonia 4.1.9](https://www.nuget.org/packages/Mapsui.Avalonia/4.1.9) и [ReactiveUI 20.4.1](https://www.nuget.org/packages/ReactiveUI/20.4.1) содержат совместимые managed-цели, включая netstandard2.0. Это основание проверить повторное использование текущего UI, а не доказательство запуска нативных библиотек на Win7.
- [Avalonia 12 убрала .NET Framework и .NET Standard](https://docs.avaloniaui.net/docs/avalonia12-breaking-changes). Для legacy-ветки нельзя автоматически обновлять Avalonia до 12; понадобятся зафиксированные и проверенные версии всей цепочки зависимостей.

## Сравнение вариантов

| Вариант | Что остаётся общим | Что потребуется | Выбор |
|---|---|---|---|
| Avalonia 11 + host net48 | Алгоритмы, контракты, ViewModels, XAML, карта и жесты | Совместимые цели библиотек, адаптация API, проверка нативных зависимостей | Первый кандидат: минимальное дублирование UI |
| WPF net48 + общие библиотеки | Domain/Application, маршрутизация, часть ViewModels и хранения | Отдельные XAML, карта, жесты, стили и UI-тесты | Резерв, если нативный Avalonia/Mapsui smoke-test не проходит |
| Текущий Desktop net8 на Win7 | Весь исходный код | Неподдерживаемый на этой ОС runtime | Не считать решением |
| Отдельная legacy-сборка на .NET 6 | Почти весь код | Устаревший runtime, проверка зависимостей и сопровождение | Не основной путь |
| Браузерный UI/WebView2 | Часть бизнес-логики | Другой UI, офлайн-хост, замороженный движок Win7 | Добавляет миграцию и не устраняет ограничения ОС |

## Как сохранить единое ядро

Основной Desktop и Android остаются на современных целях. Domain/Application/Infrastructure/Persistence/ViewModels и общий UI получают совместимую цель там, где это подтверждено сборкой, обычно `netstandard2.0` вместе с текущей целью. Legacy host содержит точку входа и настройки Win32/рендеринга. Исходники общего алгоритма и UI не копируются в новый проект.

Перед добавлением целей устранить реальные несовместимости текущего кода:

- `double.IsFinite`, `Math.Clamp`, `SHA256.HashData`, `Convert.ToHexString`, перегрузки файлового и асинхронного I/O. Небольшие совместимые реализации держать в одном общем месте, а не повторять по проектам.
- Records потребуют совместимого `IsExternalInit`; проверить Index/Range и прочие используемые API отдельно от версии языка C#.
- Default interface implementation в `IGeodataRepository.QueryMapAsync` не подходит runtime .NET Framework. Сохранить контракт явным методом с реализациями адаптеров либо выделить отдельный интерфейс отображения карты.
- Проверить точные версии System.Text.Json, Microsoft.Data.Sqlite/SQLitePCLRaw, SkiaSharp, HarfBuzz, Mapsui, ReactiveUI/Fody и DI; наличие netstandard-цели не гарантирует совместимость их нативных DLL.

При необходимости платформенные различия ограничиваются адаптерами хранилища, clipboard/launcher и рендеринга. Текущий SQLite-пакет Беларуси должен использоваться обеими сборками без отдельной копии алгоритма или конвертации данных для WPF.

## Что должно подтвердить выбор

До полноценной миграции собрать маленький net48-прототип с текущими Avalonia 11/Mapsui и SQLite. На Windows 7 SP1 x64 с .NET Framework 4.8 проверить старт, загрузку полной Беларуси, программный рендеринг при проблемном GPU, pan/zoom, ввод, clipboard, построение и отмену маршрута, чистую установку без SDK и работу без сети. Зафиксировать ОС/KB, GPU/драйвер, версии нативных DLL, commit SHA и логи.

В текущей среде нет Windows 7 VM: это исследование и выбор первого кандидата, не подтверждённая реализация платформы. Если прототип выявит неустранимую несовместимость нативного стека, переходить к WPF net48, сохранив уже подготовленные общие библиотеки. Устанавливать отдельный WPF UI до этой проверки преждевременно.
