# Аудит и план рефакторинга маршрутизации

Исходная ревизия: `062786c12cf71e9ace9e0be5d029b5ceae09f925` (`main` после merge PR #42).
Исходный Release-прогон: **374/374 xUnit, 0 ошибок, 0 пропусков**.
Предварительный прогон 325 тестов на `c00205c` до merge не является baseline этого PR.

## До изменений

| Компонент | Создание и состояние | Ответственности / проблема |
| --- | --- | --- |
| `GridRoutePlanner` | DI singleton; хранит последний подготовленный регион | Проверка ввода, область, сетка, локальный кеш рёбер, профили, метрики, похожесть, ошибки, четыре определения логов |
| `PreparedRoutingAreaCache` | Обычный экземпляр планировщика; одна запись под lock | Ограниченный кеш по bounds/cell/preferGas; повторная подготовка вне lock допустима, отмена не публикует запись |
| `RouteGeometryBuilder` | Поле планировщика, получает pathfinder через конструктор | Соединяет legs; создаёт callback стоимости, передаёт локальный GridEdge дальше в A*; вызывает постобработку evaluator |
| `AStarGridPathfinder` | DI singleton без полей расчёта | Создаёт граф, соединители и порталы, выполняет A*, восстанавливает координаты; семь аргументов и NTS в ядре |
| `GridGenerator` | DI singleton без изменяемого состояния | Геометрия регулярной сетки и подбор шага по фактическому бюджету узлов |
| `TerrainEvaluator` | Последняя подготовленная область; разделяется между запросами | Читает WKB, строит индексы, проверяет сегменты, выбирает мостовые splices, упрощает путь, собирает контакты |
| `TerrainRules` | Набор неизменяемых правил | Делегирует политику Domain; отсутствие записи сейчас молча пропускается |
| `GasCrossingIndex` / `RoadContactAnalyzer` | Обычные подготовленные индексы | Поиск газовых кандидатов / контакты итоговой линии; газовые WKB проецируются повторно |

Цепочка вызовов: `MapViewModel.BuildRoutes -> RouteCalculationService.BuildAsync -> PlanningSession.BuildAsync -> GridRoutePlanner.PlanAsync -> PreparedRoutingAreaCache.GetAsync -> GridGenerator.Generate -> RouteGeometryBuilder.Build -> IGridPathfinder.FindPath -> TerrainEvaluator.EvaluateForSearch -> RouteCostCalculator.Calculate`.

Состояние поиска (очередь, родители, расстояния), локальный GridEdge-кеш, список альтернатив и диагностика профилей принадлежат одному расчёту. Подготовленные геометрии живут дольше и должны оставаться только для чтения. SQLite возвращает исходные WKB через `IGeodataRepository`; Infrastructure не зависит от Persistence.

Полезные решения сохраняются: DI-точки генератора и поисковика, восемь соседей, радиус подключения **8 ячеек**, явные порталы, проверка всего сегмента, евклидова нижняя оценка с `MinimumCostPerMetre`, 48 шагов уточнения сетки, фиксированный мостовой допуск 2 м, одна подготовленная область и независимый кеш каждого расчёта.

## Выбранные границы

Рассмотрены сохранение callback-контракта с косметическим выделением методов и выделение графа с отдельным ядром A*. Выбран второй вариант: он устраняет передачу двух callback через промежуточный builder и позволяет тестировать A* на обычном взвешенном графе. Иерархический поиск, другие эвристики и новая инженерная семантика не вводятся.

- `GridEdgeEvaluationCache`: обычный объект расчёта; симметричные ключи, nullable факты, счётчик уникальных вычислений; без DI и интерфейса.
- `IRoutingGraph` / `GridSearchGraph`: единственная новая точка абстракции; topology/cost/heuristic вне A*, стабильный порядок соседей. Контракт Application/Domain сохраняется; контракт подменяемого поисковика Infrastructure становится типизированным.
- `PreparedTerrainData`: только подготовленная пространственная информация, одна проекция каждого WKB, без очереди поиска, логгера или состояния профиля. Мостовые коридоры, guides и порталы входят в этот снимок; отдельный сервис мостовых индексов не требуется.
- `RouteGeometryPostProcessor`: упрощение, мостовые splices и значимые точки с одной проверкой сегментов; evaluator больше не строит полный путь. Подготовленные мостовые данные не зависят от evaluator, циклической композиции нет.
- `RouteAlternativeBuilder`: проверка результата, метрики, сходство и сборка альтернатив; сохраняет порядок профилей, идентификаторы и включительный предел длины.
- `RoutingLog`: static source-generated logging с прежними event IDs, именами, уровнями и полями; не DI-сервис.

Контракт `IGridPathfinder` в Infrastructure теперь принимает `IRoutingGraph` и token, возвращает путь из node IDs либо null. Отсутствие пути переводит в прежний `NoRouteInSearchArea` владелец геометрического leg; ошибки подключения остаются в grid graph. Это намеренное изменение внутренней для приложения точки подмены Infrastructure: все DI-подмены мигрируют на новый контракт. Поддерживать параллельно прежние два callback и новый граф означало бы сохранить устраняемую связанность. Контракты Application/Domain и наблюдаемые причины ошибок не меняются.

Синтетический тест 30 км теперь измеряет реальный `GridSearchGraph` с оценкой геометрии и кешем, а не идеализированные callback расстояния. Поэтому его новые timing/uniqueEdges не сравниваются напрямую с историческим числом вызовов callback; сравнение производительности выполняется на неизменном внешнем Verify benchmark и на повторном реальном маршруте.

## Последовательность одного PR

1. Зафиксировать baseline JSON контрольных маршрутов и Release-замеры существующим `benchmark_routes.py`.
2. Выделить кеш рёбер; проверить повтор, обратное направление, null, профили, независимость и параллельные запросы.
3. Отделить построение grid/portal-графа от A*; проверить простой граф, стоимости, отсутствие пути, эвристику, отмену и восстановление; сохранить existing grid/portal scenarios.
4. Выделить подготовленные геометрии и постобработку; сохранить порядок NTS-операций, допуски, мостовые splices и цены.
5. Вынести сборку альтернатив и определения логов; сократить координатор.
6. Отдельным исправлением с RED/GREEN закрыть пропуск отсутствующих/неизвестных правил; все существующие нейтральные виды остаются нейтральными.
7. Упростить именованные вычисления сетки/области, добавить содержательные XML-контракты.
8. Добавить `routing-internals.md` с фактическими UML class/sequence diagrams и инструкцией расширения; согласовать остальные документы.
9. Сравнить baseline с результатом, выполнить общие gates, независимое ревью и CI одного PR; merge не выполнять.

## Контроль сохранения поведения

Golden-набор исключает случайный Guid, но сохраняет порядок альтернатив, координаты, все RouteMetrics, значимые точки, дорожные контакты и идентификаторы газа. Числа сравниваются с абсолютным допуском 1e-6; для координат 1e-9 градуса (примерно 0,1 мм по широте). Целые идентификаторы и счётчики сравниваются точно. Допуски не меняются ради прохождения рефакторинга.

Существующие тесты отдельно сохраняют отмену/ревизии, узкие препятствия, граничное покрытие, предельную длину, мосты и газ, адаптивную сетку и лимит ресурсов. Новые tests покрывают выделенные контракты; дублировать всю существующую интеграционную матрицу не требуется.

Числа производительности и окончательные результаты добавляются после измерений. Для сравнения используются одинаковые Release SDK, пакет и точки без параллельной сборки. Отдельное время старого A* и построения графа недоступно без изменения baseline-инструмента: сравниваются общий поиск/подготовка и существующие диагностические показатели; неполученные показатели явно отмечаются NOT VERIFIED.

## Проверка скорости после рефакторинга

Условия: Linux x64, SDK 8.0.427 / runtime 8.0.33, Release `-warnaserror`, тот же
SQLite checksum `a9063695af548db6fd11a5e5115124be6ac78e3d82698abf5f339774adaa8d1b`,
тот же сценарный JSON и неизменённый `tools/benchmark_routes.py`, 120 с на сценарий,
heap limit 1536 MiB. Инструмент видит 3 CPU; текущая cgroup-квота — 2 CPU.
Холодный процесс не означает очищенный файловый кеш ОС. Во время замеров
сборки и другие тесты не запускались.

Первые три последовательных post-refactor прогона дали медианы 13097 / 4627 /
13797 мс против утренних 10634 / 3760 / 9967 мс. Они **не отброшены**:
`artifacts/routing-refactor/final-benchmark*` сохраняет все результаты. В этой
серии load average был около 1.1–1.2 против 0.27–0.60 утром; разброс затрагивал
и подготовку. Сравнение разных временных окон не позволяет уверенно приписать
разницу коду, поэтому выполнен дополнительный чередующийся A/B-эксперимент.

Исходники `062786c` экспортированы через `git archive` в отдельный собственный
`.git/routing-architecture/baseline-source`, восстановлены с `--locked-mode`
