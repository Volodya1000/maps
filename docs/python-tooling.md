# Зачем проекту Python

Python в репозитории — язык инструментов разработки, подготовки данных и проверки сборок. Готовое приложение построено на C#/.NET и не запускает Python. У Android APK нет разрешения INTERNET; пользовательскому маршруту не нужны Python, uv или сетевые сервисы.

## Где используется Python

| Файл или каталог | Назначение | Почему это отдельный скрипт |
| --- | --- | --- |
| `tools/GeodataPreparation/` | Проверяет источник OSM, распаковывает PBF, классифицирует/упрощает геометрии, строит SQLite и R-tree, пишет манифест и контрольные суммы | Это специфичный конвейер подготовки набора данных, а не задача приложения. Инструмент запускается и локально, и в CI одной версией. |
| `tools/check.py` | Общий запуск lint, .NET desktop-проверок, подготовки тестовых данных, browser/DEM smoke test и Android Release publish | Локальный pre-commit/pre-push и GitHub Actions должны выполнять одинаковые команды. Python даёт один понятный диспетчер с проверкой зависимостей и таймаутами. |
| `tools/check_fragments.py` | Проверяет наличие непустого changelog-фрагмента среди изменений относительно базовой ветки или в staged index | Проверка понимает формат Towncrier и Git diff конкретного PR; готовый action не знает правила проекта. |
| `tools/check_network.py` | Разбирает системную трассу `strace` и проверяет отсутствие сетевых обращений в уже собранном приложении | Это проверка результата запуска, а не сборка/доставка артефакта. В CI она доступна той же командой, что и локально на Linux. |
| `tools/android_smoke.py` | Устанавливает APK в Android emulator через adb, проверяет старт, рестарт и сигнал готовности карты, сохраняет доказательства | Android Emulator Runner поднимает эмулятор, но критерии готовности именно этого приложения задаёт наш проверочный сценарий. |
| `tools/install_belarus.py` | Скачивает закреплённый по SHA APK, проверяет и устанавливает полный пакет Беларуси в `artifacts/`, при необходимости запускает текущую desktop-сборку | Это специальная команда подготовки большого офлайн-пакета и проверки его совместимости; данные и APK нельзя коммитить в Git. |
| `spikes/MapLibre/serve.py` | Поднимает локальный HTTP сервер для browser/DEM smoke test | Страница должна обслуживаться по HTTP локально, а сервер гарантированно запускается и завершается вместе с тестом. |
| Небольшие inline Python-блоки в `publish-preview.yml` | Сверяют SHA, состав и результаты стартовой проверки релизного APK перед публикацией | Это шаги только публикации GitHub Release; локально входной пакет можно проверить через `tools/install_belarus.py --verify`, а сборку/смоук-тесты выполняют `offline-packages.yml` и `tools/android_smoke.py`. |
| `tests/tooling/` | Проверяет правила changelog и установщик на маленьких временных репозиториях/архивах | Это быстрые поведенческие тесты Python-инструментов, а не копии больших производственных данных. |

Версии Python-пакетов для корневых инструментов закреплены в `pyproject.toml` и `uv.lock`; подготовка геоданных имеет отдельные `pyproject.toml`/lockfile, чтобы тяжёлые зависимости обработки PBF не попадали в обычный набор hooks.

## Почему не заменить всё готовыми GitHub Actions

Actions уже используются там, где они решают общую инфраструктурную задачу: checkout, установка .NET/Java/Android SDK/Node, запуск Android emulator, upload/download artifact и release orchestration. Они хорошо стандартизуют окружение и сохраняют логи.

Они не заменяют project-specific проверки: проверку схемы наших геоданных, контроль суммы APK, проверку отсутствия `INTERNET`, готовности реальной офлайн-карты после запуска Activity и требования к changelog-фрагментам. Такие правила всё равно пришлось бы описать кодом или командой shell, причём отдельно для локального запуска. Поэтому Python оставлен для коротких переносимых проверок и диспетчера команд; GitHub Actions отвечает за runner и платформенные ресурсы. Скрипты намеренно не пересоздают эмулятор, Android SDK, компилятор или GitHub artifact service.

Команды для разработчика перечислены в [`development.md`](development.md); соответствующие CI jobs находятся в [workflow](../.github/workflows/ci.yml).
