# Оценка тестов и SOLID

Аудит 2026-10-23, после исправления CI и рефакторинга ViewModels. Это оценка проверяемых сценариев и чувствительности тестов к ошибкам; процент line/branch coverage не измерялся. Количество тестов не выдаётся за полноту покрытия.

## Критерии Владимира Хорикова

В [Unit Testing Principles, Practices, and Patterns](https://www.manning.com/books/unit-testing) рассматриваются защита от регрессий, устойчивость к рефакторингу, скорость обратной связи и сопровождаемость. В авторских материалах [наблюдаемое поведение](https://khorikov.org/posts/2019-11-11-people-behavior-and-unit-testing/) противопоставляется деталям реализации; [избыточные mocks](https://khorikov.org/5-unit-testing-mistakes/3-mocks-arent-your-friend/) могут привязывать тесты к внутренним взаимодействиям. Здесь эти критерии применены к конкретным пользовательским сценариям.

| Критерий | Что сохраняем | Что исправлено / остаётся |
|---|---|---|
| Защита от регрессий | Реальные геометрии, ограничения препятствий, разрешения переходов, сохранение настроек и фактический слой карты | Добавлен `NotEmpty` перед проверкой каждого маршрута: пустой результат не должен проходить проверку допустимого обхода/перехода |
| Устойчивость к рефакторингу | Географические конечные точки, порядок пользовательских точек, ошибка/повторная загрузка, данные после рестарта | Удалены тест «команды не null», точные внутренние версии перерисовки и проверки числа вызовов планировщика; тест перестановки проверяет геометрию результата |
| Быстрая обратная связь | Маленькие синтетические наборы и реальные локальные SQLite-данные без загрузки сети в тестах | ViewModel-тесты изолируют scheduler; ожидания имеют таймаут. Browser/Android проверки отделены от быстрых тестов |
| Сопровождаемость | Небольшие arrange/act/assert, доменные названия | SQLite, манифесты и временные каталоги вынесены в disposable-фикстуры; raw touch-инъекция находится в одном адаптере Avalonia |

Публичное состояние не всегда является деталью реализации. Например, текст ошибки и выбранная геометрия используются UI, а настройки, загруженные после рестарта, доступны пользователю. Их проверять нужно. Внутренний счётчик вызовов, private-метод или точное число уведомлений не заменяют проверку результата. Снимки сохранённых значений, UI-контракт доступности «Сохранить» и отсутствие устаревшего маршрута — наблюдаемое поведение.

## Покрытые сценарии и ограничения

| Область | Проверяемое поведение | Оставшиеся проверки |
|---|---|---|
| Domain/маршрутизация | Конечные и промежуточные точки, реальные метры, запас кабеля, запрет тонких препятствий, согласованные переходы, разные профили и отсутствие дубликатов | Более сложные случайные геометрии и очень узкие допустимые коридоры |
| PlanningSession/Map | Изменение точек отменяет старый результат; перестановка пересчитывает актуальный порядок; старый запрос карты не перезаписывает новый; ошибка не стирает уже показанные объекты | Длительные серии пользовательских изменений на целевых устройствах |
| Настройки | Начальные значения в настоящих контролах, dirty-state, возврат исходного значения, успешная/неуспешная запись, предупреждение перед уходом/закрытием | Ошибки файловой системы на реальных Windows/Android и конкурентная внешняя запись |
| Startup | Ошибка подготовки, повторная попытка, отмена без публикации устаревшего экрана; UI открывается после подготовки | Длительная распаковка полной карты на слабых устройствах |
| UI | Raw touch-перестановка и удаление своей строки, удержание с видимой обратной связью, прокрутка без перестановки, реальное переключение геометрии Mapsui | Pinch/multitouch и системные жесты на физическом Android |
| Persistence | Повреждённый/отсутствующий пакет, настройки после рестарта, недопустимая запись не стирает сохранённое, упрощённый display-слой не открывает препятствие | Нативные SQLite DLL на Windows 7, реальные ошибки диска |
| Автономность | Linux-процесс Verify без внешних вызовов, Browser без внешних запросов, отсутствие INTERNET в APK | Полный сетевой аудит каждой целевой ОС |

Полная Беларусь проверяется отдельным инструментом: обзор страны и исходные дороги у шести областных центров. Это подтверждает поставку и доступность данных, но не полноту OSM и не корректность всех возможных маршрутов. Проверка Windows 7 остаётся отдельной задачей.

UI-адаптеру тестов приходится находить реальные элементы Avalonia и вводить touch-события через совместимый с версией framework мост. Это локализованная зависимость интеграционного теста от UI-framework; private-методы приложения не вызываются. Готовность элемента определяется hit-test и ограниченным ожиданием, а не произвольной задержкой отрисовки. В тесте прокрутки длительность контакта намеренно превышает порог удержания, потому что это часть пользовательского входа.

## SOLID

| Принцип | Оценка текущего проекта | Что сделано / следующий шаг |
|---|---|---|
| SRP | Domain, алгоритм, persistence и UI разделены. MapAreaLoader, RouteMetricsFormatter и WaypointListProjection уже отделены от MapViewModel | Shell/Startup/Settings теперь создают команды и подписки отдельно от действий. Укорочение конструктора улучшает чтение, но само по себе не доказывает SRP; ViewModel остаётся координатором состояния экрана |
| OCP | Планировщик и источники данных подключаются через контракты, профили стоимости задаются данными | Новые виды местности по-прежнему затрагивают enum, подготовку и оценку; не обещаем расширение без изменения всех политик |
| LSP | Глубокой иерархии моделей нет; реализации репозитория должны сохранять семантику исходных данных | Тест на display-упрощение защищает главное правило: отображение не меняет данные препятствий маршрутизации |
| ISP | Интерфейсы settings, clipboard, planner и session небольшие | Geodata объединяет исходные и display-запросы. При разных источниках можно разделить интерфейсы; для net48 в любом случае убрать default interface implementation |
| DIP | Domain не зависит от Avalonia/SQLite; Application объявляет контракты, Bootstrap выбирает реализации | Ссылки Shell на конкретные ViewModels остаются внутри presentation-слоя. Дополнительный интерфейс для каждого приватного метода не добавлялся |

Длинная фабрика в Bootstrap — composition root, а не основание переносить создание сервисов в ViewModel. Взаимодействие с clipboard через `IClipboardService` соответствует границе UI/ОС. Нет оснований создавать отдельный сервис только ради одной строки делегирования.

SQLite-фикстура создаёт отдельный каталог и БД для каждого теста. Она не использует разделяемую изменяемую БД и не подавляет ошибки удаления: подавление могло бы скрыть утечку SQLite handle на Windows. Реальный repository отключает pooling и закрывает соединения, поэтому правильная очистка проверяема.
