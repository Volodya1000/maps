# Оптимизация поиска

Подготовка находится в Infrastructure, правила стоимости — в Domain, UI не хранит GIS-индексы. PreparedRoutingAreaCache хранит только последнюю расчётную область для одного экземпляра репозитория. Ключ включает только точные границы; размер ячейки и предпочтение газовых переходов не меняют подготовленные данные; пакет репозитория неизменяем в течение жизни планировщика. При замене пакета нужно создать новый репозиторий и планировщик. Память не растёт с числом запросов. Отменённая или неудачная подготовка не заменяет успешную запись. Сам поиск и проверка сегментов продолжают выполняться заново.

`GridRoutePlanner` координирует область, сетку и профили. `PreparedTerrainData` владеет подготовленными геометриями и индексами; каждый WKB проецируется один раз, в том числе для газовых кандидатов. `TerrainEvaluator` проверяет сегмент. `GridSearchGraph` создаёт допустимые переходы и цены, `AStarGridPathfinder` получает только `IRoutingGraph` и token и возвращает node IDs. Два callback больше не передаются через `RouteGeometryBuilder`.

`RouteGeometryBuilder` владеет `GridEdgeEvaluationCache` одного расчёта: симметричный ключ, включая null для непроходимых рёбер, и общие факты для всех профилей. Подготовленный снимок может разделяться параллельными запросами, этот словарь — нет. `RouteGeometryPostProcessor` упрощает и выравнивает полный маршрут; `RouteAlternativeBuilder` считает метрики и удаляет сходные альтернативы. `TerrainRules` проверяет полноту всех `TerrainKind` и согласованность запретов с Domain; пропуск правила не разрешает местность. [Подробная последовательность, UML и расширение правил](routing-internals.md).

Логи отдельно показывают запрос SQLite, WKB/проекцию/STRtree и последующий расчёт. Нулевые времена подготовки при повторе обозначают повторное использование. Индекс не кэшируется для всей Беларуси: это потребовало бы слишком много памяти телефона.

Иерархический поиск и точный SQL-фильтр по прямой пока не включены: прямой коридор может исключить единственный мост или необходимый обход. Нужны сравнение с полным поиском и сценарии узких проходов. Сначала следует измерить холодный и повторный расчёты на устройстве.

DEM нельзя заменить эвристическими высотами: нужен проверенный локальный источник высот с лицензией, покрытием и обработкой отсутствующих значений. Пока подъём остаётся неизвестным. Неоднородная сетка требует новой реализации графа с сохранением проверки всех сегментов; явные мостовые порталы уже включены в GridSearchGraph, а существующее выравнивание геометрии моста остаётся действующим.

Контрольный локальный прогон по Минску (53.9490,27.5180 → 53.9500,27.5190, Linux под strace) до уточнения эвристики: SQLite 86 мс, подготовка 97 мс, расчёт 2171 мс, 656 проверенных рёбер. Это единичный замер, не прогноз для Android.

После PR #44 исключены неиспользуемые параметры ключа/контракта подготовленной
области. Изменение ячейки использует прежние пространственные
индексы, но создаёт независимые evaluator/mesh/search state и пересчитывает
альтернативы. Хранится одна область на неизменяемый repository/planner;
параллельные miss не объединяются ценой нового сервиса или многорегионного кеша.
