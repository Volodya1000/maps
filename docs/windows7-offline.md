# Автономный запуск на Windows 7 x86

## Подтверждённый вариант

18 ноября 2026 года Desktop из `main` (`584ac376b2dc5ed9d5a05b7d6aed19534a5da789`) вручную запущен на реальной Windows 7 SP1 x86 в отдельной виртуальной машине. Карта Минска отобразилась, приложение работало без установленного `dotnet` и без Mono. Это проверка запуска конкретной сборки, а не обещание поддержки всех редакций Windows 7 и драйверов.

Для этого используется **самодостаточная папка x86**. В ней находятся:

- `CableRoutePlanner.Desktop.exe` и библиотеки приложения;
- встроенный .NET 6 x86 runtime (`hostfxr`, `hostpolicy` и нужные DLL);
- нативные DLL Avalonia, Skia, SQLite и Mapsui;
- `Data/` с маленьким офлайн-пакетом Минска, включая `geodata.sqlite`;
- `SHA256SUMS.txt` с контрольными суммами файлов.

Поэтому на целевом ноутбуке не нужны Интернет, Mono, отдельная установка .NET или NuGet. Все файлы папки обязательны: нельзя переносить только EXE или запускать его после удаления DLL и каталога `Data`.

## Как получить и перенести пакет

1. На компьютере с Интернетом откройте успешный запуск GitHub Actions **Windows 7 x86 offline desktop** для нужного PR или ветки `main`.
2. В разделе **Artifacts** скачайте `CableRoutePlanner-Windows7-x86-<commit>` и распакуйте ZIP.
3. Скопируйте целиком распакованную папку `windows7-x86` на флешку.
4. На ноутбуке Windows 7 SP1 x86 скопируйте эту папку в доступный для записи каталог, например `C:\CableRoutePlanner`.
5. Запустите `CableRoutePlanner.Desktop.exe` из этой папки.

Это пока переносимая папка, а не MSI-установщик. Для автономного применения это намеренно проще и надёжнее: установка не обращается к сети и не меняет системные компоненты.

## Сборка пакета разработчиком

На Windows Server/Windows 10/11 с SDK из `global.json`:

```powershell
.\tools\Windows7Compatibility\build-win7-x86.ps1
```

Результат находится в `artifacts/windows7-x86`. Скрипт восстанавливает зависимости только из зафиксированных `packages.win7.lock.json`, публикует `net6.0/win-x86` как self-contained и создаёт `SHA256SUMS.txt`.

`net6.0` выбран осознанно: это последний runtime семейства .NET, который практически удалось запустить на Windows 7. Он снят с поддержки Microsoft, поэтому этот путь является legacy-совместимостью и должен проверяться на настоящей Windows 7 для каждого существенного обновления Avalonia, Mapsui, Skia, SQLite или runtime.

## CI и границы проверки

Workflow `.github/workflows/windows7-x86.yml` запускается для каждого PR и каждого push в `main`. Он собирает полный self-contained x86 пакет с той же небольшой картой Минска, проверяет наличие EXE, базы и состава файлов, затем публикует его как artifact. Hosted runner не является Windows 7 и не может подтвердить отрисовку, мышь, драйверы или производительность: для этого artifact нужно вручную проверить на целевой ОС.

Для стенда Windows 7 допускается передача архива по WinRM Basic или через флешку. При проверке по WinRM копируйте ZIP/папку в профиль интерактивного пользователя и запускайте EXE именно в его сеансе; запуск из служебного сеанса WinRM не доказывает видимое окно. Не добавляйте в репозиторий адреса, пароли или образы виртуальных машин.

## Диагностика

На проверенной ВМ не были нужны установленный .NET и Mono. Если на другой Windows 7 появляется ошибка `hostfxr`, `api-ms-win-*` или приложение не создаёт окно, сначала зафиксируйте точный текст и редакцию ОС. Нужен Windows 7 SP1; для части конфигураций Microsoft указывает дополнительные обновления ОС и Microsoft Visual C++ Redistributable как предпосылки запуска .NET 6. Эти компоненты следует заранее положить на носитель и устанавливать офлайн только при подтверждённой ошибке, а не скачивать на целевом ноутбуке. См. [требования установки .NET для Windows](https://learn.microsoft.com/dotnet/core/install/windows).

## Известные последующие работы

- На проверенной Windows 7 x86 карта отображается, но панорамирование, масштабирование и поворот субъективно работают хуже, чем на Android. Это отдельная задача производительности и взаимодействия; данный PR намеренно не меняет карту.
- Раздел «Прокладка» связан с GPS и должен быть доступен только на Android. Его скрытие в Desktop — отдельная UI-задача, чтобы не смешивать её с подтверждённой поставкой Windows 7.
