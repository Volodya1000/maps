# Что стоит перенять из OsmAnd

Дата исследования: 26 ноября 2026. Статус: **предложения для согласования, не утверждённая реализация**. Этот PR содержит только документацию; расчёт, Android и лицензирование проекта не меняются.

## Вывод

OsmAnd полезен как источник проверенных сценариев работы с офлайн-картой, высотами и треками. Рекомендуется развивать нынешний планировщик, первым этапом добавить анализ высот готовой трассы, затем отдельно согласовать влияние рельефа на поиск. Для полевых обследований можно использовать OsmAnd параллельно; обмен GPX уменьшил бы необходимость повторять его навигационные функции.

Не знать о нём раньше — упущенная возможность исследования аналогов, но не доказательство, что собственное приложение было ошибкой. Здесь уже реализованы специфические правила кабельной трассы: стоимость леса и полей, препятствия, кандидаты переходов, инженерные согласования, сравнение альтернатив. Навигация по дорогам и тропам не доказывает пригодность места для прокладки кабеля. Решение о прекращении проекта стоит принимать по проверке этих задач, а не по красоте карты конкурента.

OpenStreetMap — база геоданных; OsmAnd — отдельное приложение на её основе. Наличие объекта в OSM не подтверждает право строительства или инженерную пригодность.

## Высоты: два разных результата

### 1. Анализ уже рассчитанного маршрута

Получить DEM-выборки **вдоль окончательной геометрии**, включая промежуточные точки и геометрию переходов. Показать расстояние по горизонтали на X, высоту в метрах на Y, минимум/максимум, суммарный подъём/спуск, продольный уклон и участки без данных. Курсор на графике связан с картой; выбор альтернативы обновляет обе проекции. Для телефона нужен раскрываемый блок под картой, читаемые единицы и работа касанием без hover.

Высота «над уровнем моря» требует определённого вертикального датума. В карточке источника хранить датум, разрешение, версию и происхождение данных. GPS-высоту и DEM нельзя смешивать без проверки их систем отсчёта. Copernicus GLO-30 — DSM, включая растительность и строения; это не точная поверхность грунта. Нужна проверка качества для Беларуси и мест переходов.

Суммарные подъём и спуск зависят от шага и фильтрации. Предложение: сохранять исходные выборки и параметры обработки, статистику считать по документированному профилю, график упрощать отдельно. Не подменять отсутствующую высоту нулём и не соединять неизвестный участок линией, создающей впечатление измерения. При неполном покрытии показывать неполноту и не выдавать полный итог за достоверный.

Длина по поверхности приближённо равна сумме `sqrt(d² + Δh²)` по выборкам; она не равна горизонтальной длине плюс суммарный подъём. Геометрическая поправка не заменяет технологический запас, петли, подвес или глубину траншеи. Подробные формулы, риски сферической длины и критерии эксперимента уже есть в [исследовании длины по рельефу](terrain-aware-cable-length-proposal.md). Новый документ его не отменяет и не объявляет реализацию согласованной.

### 2. Выбор маршрута с учётом рельефа

Красивый график после поиска **не меняет выбранную трассу**. Для этого нужно оценивать рельеф на каждом рассматриваемом ребре, включая прямые соединения, порталы и последующее упрощение геометрии. Проверка только высот концов пропустит холм между ними.

Предлагаемая модель: существующая стоимость плюс неотрицательная надбавка за длину и крутизну участка; жёсткий предел уклона только после инженерного согласования технологии прокладки. Продольный уклон и поперечный склон — разные характеристики; одна не заменяет другую. Туристическое предпочтение «меньше подъёмов» не является правилом прокладки кабеля, а направление движения не должно случайно менять стоимость симметричной технологии.

Все веса, пределы с единицами и правила неизвестных высот централизуются в Domain. DEM-чтение и интерполяция не попадают в Domain; Application задаёт контракт, Persistence читает пакет, Infrastructure выбирает высоты и выполняет поиск, ViewModels/UI показывают результаты. Реальные интерфейсы добавлять только после проверки нужного контракта. DI остаётся в Composition Root.

Цена поисковых рёбер и итоговая оценка должны использовать одни правила. Упрощение не должно срезать склон, запрещённый при поиске. Допустимость эвристики A* нужно доказать для новой функции стоимости; существующая нижняя оценка сохраняется лишь при подтверждённой неотрицательной надбавке и прежнем нижнем ограничении базовой стоимости. Изменение DEM, профиля или точек отменяет работу и исключает публикацию устаревших результатов. Требуется ограниченный кеш высот с учётом версии пакета и измерение памяти/времени на Android.

В просмотренных алгоритмах есть собственные пороги фильтрации. Не переносить их числа без эксперимента: фильтр, полезный для туристической статистики, способен скрыть инженерно значимый перепад. Нужны проверки плоского профиля, малого холма, шума, пропусков, повторяющихся координат и обращения направления. Эти файлы анализируют профиль; они сами по себе не доказывают, как рельеф участвует в стоимости маршрутизации OsmAnd.

Java/Kotlin-код Android и его графические зависимости нельзя непосредственно подключить к Avalonia/C#. Перенос означает новую интеграцию, тестирование и сопровождение. Для первой версии предпочтительна собственная реализация математических правил по требованиям проекта; буквальное портирование — отдельное решение после оценки лицензии и качества.

## Лицензии и границы заимствования

Официальный LICENSE указывает GPLv3 для основного кода, исключения для сторонних компонентов, отдельные условия для оформления и ресурсов. Указание MIT для входящих pull requests **не делает весь репозиторий MIT**. Перевод исходника с Kotlin на C# не устраняет условия заимствованного кода.

До копирования конкретного файла требуется зафиксировать его SHA, заголовки, авторов, зависимости и лицензию; определить условия распространения производной работы, предоставления соответствующих исходников и уведомлений. В maps не найден корневой LICENSE: отсутствие такого файла не означает разрешение на произвольное использование и не решает совместимость с GPL. Выбор лицензии проекта и условий будущего распространения остаётся решением владельца. Сам этот документационный PR его не принимает.

Для UI/UX и artwork OsmAnd заявлены CC-BY-NC-ND 4.0, отдельные proprietary-ресурсы и требование письменного разрешения для публикации использующих их приложений в перечисленных магазинах. Поэтому не копировать иконки, макеты и ресурсы «потому что приложение открыто». Сделать собственное оформление графика. Условия OSM/ODbL и выбранной поставки DEM проверяются отдельно от лицензии программы. Это предварительная проверка по LICENSE, не юридическое заключение о конкретном будущем переносе.

## Варианты развития

1. **Собственное приложение + изучение подходов OsmAnd (рекомендация).** Сохраняет инженерные правила и Avalonia/Desktop/Android; высоты и UX добавляются постепенно. Стоимость — собственная реализация и поддержка.
2. **Собственное приложение + обмен GPX с OsmAnd.** Позволяет раньше использовать готовую полевую навигацию. GPX не переносит автоматически инженерные разрешения, стоимость и происхождение DEM: их хранить в собственном формате сессии, импорт считать внешней геометрией для повторной проверки.
3. **Расширение или fork OsmAnd вместо текущего UI.** Даёт зрелую мобильную картографию, но потребует доказать возможность маршрутизации вне дорожного графа, поддержку инженерных правил, платформ и лицензионную модель. Это исследовательская альтернатива, не очевидное сокращение работ. Перед выбором нужен ограниченный прототип на реальном кабельном сценарии.

Рекомендуется сочетание 1 и 2. Переезд целиком пока не обоснован измерениями. Существующие офлайн-карта, GPS и промежуточные точки не нужно переписывать ради сходства.

## Последовательность после согласования

| Этап | Результат для проверки | Условие перехода |
|---|---|---|
| A. Данные и качество | DEM тестового района, лицензии/датум/хеши, контрольные профили и оценка размера | Ошибки и ограничения известны; источник пригоден для задачи |
| B. Профиль готовой трассы | График, подъём/спуск, уклон, связь с картой, явные пропуски | Проверка статистики и UX на Android; прежний поиск не меняется |
| C. Обмен и обследование | Экспорт/импорт GPX без потери исходной сессии | Координаты/высоты/пропуски проверены обменом с OsmAnd; внешние точки не получают разрешений автоматически |
| D. Рельеф в поиске | Отдельно включаемый профиль с объяснимой ценой и ограничениями | Согласованы инженерные правила; маршрутизационные регрессии и замеры пройдены |
| E. Дополнительное удобство | Слои рельефа, поиск мест, избранное | Приоритет подтверждён полевым использованием |

Это порядок зависимостей, не оценка календарных сроков. GPX можно реализовать независимо от DEM после согласования приоритета.

Приёмка B: постоянная высота, холм с одинаковыми высотами концов, подъём и обратный проход, пропуски DEM, границы тайлов, окончательная геометрия перехода, смена маршрута во время анализа. Проверять результаты и инварианты, не внутренние вызовы и локализованные сообщения исключений. Нужны реальные контрольные данные, а не только синтетика.

Приёмка D: короткий крутой и длинный пологий варианты, внутренний пик на ребре, препятствия и переходы, режим без DEM, согласованность цены после упрощения, отмена/устаревание, детерминизм и замеры на телефоне. Для автономности приложение не должно обращаться к онлайн-сервисам высот: подготовка пакетов остаётся отдельным инструментом. Любой численный предел качества или времени согласовывается после базового замера, а не выдумывается в этом PR.
