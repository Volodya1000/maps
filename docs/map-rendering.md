# Полнота отображения офлайн-карты

Запись работы приложения от 29 октября 2026 показывает обрывки дорог при отдалении, наложение подписей разного масштаба и большую пустую область после перемещения и поворота.

## Причины и исправления

`QueryMapAsync` ограничивал результат первыми 500 / 1 500 / 5 000 / 6 000 объектами в зависимости от масштаба. При этом Mapsui сохранял полученный неполный тайл в кеше как успешно загруженный. Теперь пространственный запрос возвращает все объекты выбранного уровня детализации в области тайла. Пространственный индекс, подготовленные упрощённые геометрии и ограниченный кеш растровых тайлов сохраняются. Векторные объекты подготавливаются для отдельных тайлов, а не для единого слоя всех исходных данных страны. Предзагрузка ограничена одним родительским уровнем вместо трёх, чтобы не растеризовать сразу несколько больших областей на телефоне; более старые уже кешированные уровни остаются доступны для временного заполнения пропусков.

Mapsui временно показывает кешированные родительские тайлы для недостающих соседей. Новые растровые тайлы были прозрачными: через них просвечивали старые крупные подписи и дороги. `GeodataFeatureProvider` добавляет непрозрачный фон перед объектами карты. Старый уровень остаётся виден только там, где новый тайл ещё отсутствует. Фон сам по себе не объявляет успешную загрузку геоданных в Android smoke-проверке.

Ограничитель камеры учитывает всю видимую область с её поворотом. Там, где экран помещается внутри покрытия пакета, перемещение не открывает внешние пустые поля. Если при обзоре экран шире или выше покрытия, карта центрируется по соответствующей оси. Естественные поля из-за соотношения сторон остаются; их нельзя заполнить данными за пределами офлайн-пакета.

Изменения работают с существующими пакетами schema_version=1/2. Переподготовка карты не требуется. Исходные данные и правила расчёта маршрутов не меняются.

## Автоматические проверки

| Сценарий | Тест |
| --- | --- |
| Плотный тайл на каждом уровне детализации, поздний по ID участок дороги, исключение объектов вне области | `DenseMapAreaRetainsFeaturesAcrossTheWholeTile` |
| Непрозрачные углы и правильный цвет леса/фона в настоящем PNG тайла | `RasterTileHasOpaqueBackgroundAndPreservesTerrain` |
| Новый тайл закрывает старый, сосед без нового тайла сохраняет подложку | `DetailTileHidesOldLabelsWhileMissingNeighbourRetainsParentFallback` |
| Фактическая загрузка запрашивает текущий и один родительский уровень | `BasemapFetchesCurrentAndSingleParentResolution` |
| Обзор на узком экране и с поворотом, включая большие Mercator-координаты | `OverviewCameraCentersCoverageInsteadOfLeavingItAtScreenEdge` |
| Перемещение с поворотом сохраняет видимое покрытие | `PanningKeepsVisibleFootprintWithinOfflineCoverage`, `PanningKeepsMapViewportInsideCoverageAtEveryCorner` |
| Незавершённая разметка не меняет камеру | `UnarrangedViewportKeepsCameraUnchanged` |

Проверки выполняются штатным `uv run --locked python tools/check.py desktop`, включая Avalonia.Headless, настоящий SQLite/R-tree и растеризатор Mapsui/Skia. Они проверяют результаты запросов, пиксели изображений и положение камеры. Плавность жестов на конкретном Android-устройстве дополнительно проверяется на устройстве.

## Проверка полного пакета

Следующие измерения относятся к первоначальной версии исправления `711c6fb`; доработка по второй записи описана ниже.

Локально использован закреплённый пакет `CableRoutePlanner-0.2.0-Belarus.apk` из `tools/install_belarus.py`, с проверенными контрольными суммами APK и SQLite. Для базовой версии `ba589b1` и исправления получены PNG одних и тех же областей настоящим production tile provider. Размер изображения — 720 × 1100; для каждой сцены последовательно загружены 18–20 тайлов. Суммы ниже включают повторное попадание протяжённых объектов в соседние тайлы.

| Область / разрешение Mercator, м/пиксель | Строк в запросах до → после | Наибольший запрос до → после |
| --- | --- | --- |
| Обзор страны / 1 222,99 | 5 381 → 31 836 | 500 → 10 254 |
| Регион Минска / 305,75 | 7 076 → 11 677 | 500 → 4 349 |
| Минск / 76,44 | 12 366 → 16 278 | 1 500 → 4 598 |
| Детальная карта Минска / 38,22 | 52 704 → 64 967 | 5 000 → 9 544 |
| Улицы Минска / 9,55 | 23 248 → 23 248 | 1 470 → 1 470 |

В одном последовательном Release-прогоне на Linux обзор страны занял 2,09 → 2,60 с; остальные сцены — около 0,68–1,37 с. Пик working set проверочного процесса после пяти сцен составил 171,6 → 176,0 MiB. Это измерения данного проверочного процесса без интерфейса приложения и без имитации жестов; они не являются оценкой времени или памяти Android-устройства. Карта и сгенерированные PNG не входят в исходные геоданные репозитория.

## Задержки и смена масштаба на Android

На второй 40-секундной записи полнота карты улучшилась, но видны задержки появления деталей и резкая подмена растянутого обзорного изображения новым. Из видео нельзя определить GC-паузы или время UI-потока; для этого нужен профиль устройства.

В Mapsui 4.1.9 параметры `minExtraTiles` / `maxExtraTiles` переопределяли заданный кеш 96–160 тайлов размером «видимый экран + 8 / 32». После нескольких перемещений недавние масштабы вытеснялись и заново читались из SQLite и растеризовались. `OfflineRasterLayer` сохраняет фиксированные границы 96–160. Полнота пространственных запросов и один предзагружаемый родительский уровень сохраняются.

`BackgroundTileSource` допускает не более двух одновременно подготавливаемых и растеризуемых тайлов. Весь вызов растеризатора выполняется в ThreadPool, включая случай синхронного ответа repository. Закрытие карты отменяет ожидающие задания; уже начатые завершаются, после чего освобождаются ресурсы. Ошибка одного задания не блокирует следующие.

`FadingTileRenderFetchStrategy` при приближении смешивает родительский и детальный тайлы за 200 мс. По завершении детальный тайл полностью непрозрачен; незагруженные соседи сохраняют обзор. Если обзорной подложки нет, готовые детали показываются сразу. Поздний обзор не запускает обратное появление прозрачности. Стили и декодированные изображения сохраняются между кадрами. Таймер обновляет только графику, не запрашивает геоданные и останавливается по завершении перехода, даже если экран больше не рисуется, либо при закрытии карты.

Преобразование координат заполняет результирующую последовательность напрямую, сохраняя валидацию координат. Один набор стилей покрытия повторно используется для всех объектов того же типа внутри тайла; названия населённых пунктов остаются индивидуальными.

| Проверка | Тест |
| --- | --- |
| Возврат к недавней области без новых запросов геоданных | `ReturningToRecentViewportUsesCachedTiles` |
| Не более двух заданий, подготовка вне UI-потока | `RasterPreparationRunsOffUiThreadWithAtMostTwoJobs` |
| Отмена ожидающих заданий и повторное освобождение карты | `DisposingMapCancelsQueuedTilesAndLetsRunningTilesFinish` |
| Ошибка не удерживает место работника | `FailedRasterJobReleasesCapacityForNextTile` |
| Повторное использование стилей без слияния геометрии и названий | `RepeatedTerrainReusesStylesWithoutMergingGeometryOrSettlementNames` |
| Пиксели перехода на 0 / 100 / 200 / 300 мс | `DetailTileFadesOverParentWithoutAnAbruptReplacement` |
| Анимация заканчивается без новых кадров | `AnimationExpiresEvenWhenNoMoreFramesAreRendered` |
| Нет обратного мерцания от запоздавшего обзора | `LateParentDoesNotMakeAlreadyVisibleDetailTranslucent` |

Проверки анимации используют управляемое время без задержек и настоящий растеризатор Skia. Полнота карты, отсутствие наложения в завершённом кадре и ограничение камеры по первой записи также остаются в наборе проверок. Эти результаты не заменяют измерение частоты кадров и пауз на физическом Android.

В последовательном Linux Release-прогоне того же полного пакета с одинаковыми пятью камерами PNG совпали побайтно с `711c6fb`. Выделение управляемой памяти за подготовку сцен снизилось примерно на 8–14%: например, детальная сцена Минска — с 258,7 до 221,3 MiB суммарных выделений (это не объём одновременно занятой памяти). В том же прогоне её построение заняло 1 473 → 1 239 мс, обзор страны — 2 727 → 2 479 мс. Холодная загрузка по-прежнему требует чтения и растеризации; результат одного Linux-прогона не является гарантией Android FPS. Основной выигрыш повторного посещения — отсутствие новых запросов и повторной растеризации подтверждённых кешем тайлов, а не урезание данных.
