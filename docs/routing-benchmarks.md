# Дальность и измерения маршрутизации

В приложении нет лимита в километрах. Практические ограничения — границы пакета,
препятствия, шаг сетки, доступные переходы, лимит узлов и память. По умолчанию
задано 100 000 узлов, исходный шаг 25 м. На большой площади шаг автоматически
увеличивается, максимум до 2000 м. Поэтому успешный поиск на 3 км не доказывает
успех на 300 км: грубый граф может потерять узкий проход или выход из города.

Устранён выход за бюджет из-за дополнительного ряда/столбца при расчёте шага:
шаг уточняется по фактическому целочисленному числу узлов.

Сетка ограничивает площадь прямоугольника поиска, а не только расстояние между
точками. Отсутствие пути в таком графе не доказывает, что вся местность физически
непроходима. Ошибки подключения к сетке, отсутствия пути в области и лимита
ресурсов имеют отдельные причины; сообщение не приписывает любой отказ реке.
Полностью проверенный прямой маршрут сохраняется, даже если другие профили не
могут соединить точки с сеткой.

## Что доказано тестами

`LargeScaleRoutingTests` проверяет пары Минск—Брест и Витебск—Гомель на
**синтетической пустой территории**. Это проверка дальности вычислительного
графа, а не доказательство прохождения реальной Беларуси.
`ValidDirectRouteSurvivesAnUnresolvedGridForOtherProfiles` проверяет узкий сухой
коридор между водой: допустимый прямой путь не теряется из-за отказа сетки
в остальных профилях. Водные сегменты проверяются целиком отдельными тестами.

## Воспроизводимые реальные замеры

Метка PR `ci:routing-benchmark` включает отдельный job на полном пакете Беларуси
после обязательных проверок. Она требует подготовки полной карты, даже если
есть `ci:skip-full-maps`. Отчёт `routing-benchmark-<sha>` содержит JSON, геометрии
успешных маршрутов, stdout/stderr, checksum данных и условия измерения.

Сценарии заданы в `samples/routing-benchmarks.json`:

| Сценарий | Что проверяет |
| --- | --- |
| minsk-local | Небольшой реальный участок Минска |
| minsk-brest | Междугородний поиск; около 328 км по прямой |
| vitebsk-gomel | Междугородний поиск; около 311 км по прямой |

Каждый сценарий запускается в новом процессе Release с лимитом 120 секунд и
управляемой кучей 1536 MiB. Время включает загрузку пакета и проверку точек.
`completed` означает успешные маршруты; `failed`, `no_routes` и `timeout`
сохраняются как результаты измерения, а не превращаются в успешный поиск.
Необрабатываемая ошибка самого инструмента останавливает job. Отказ валидации
конкретной городской точки тоже сохраняется; его нельзя считать доказательством
невозможности соединить два города через другие точки.

Локальный запуск после Release-сборки Verify:

```sh
python tools/benchmark_routes.py --data artifacts/belarus \
  --verify-dll tools/CableRoutePlanner.Verify/bin/Release/net8.0/CableRoutePlanner.Verify.dll \
  --output artifacts/routing-benchmark --timeout-seconds 120
```

Первый локальный холодный запуск на пакете Минска дал 3 маршрута длиной
2774/3210/3747 м за 24,9 секунды полного процесса. Одновременно шла Android-сборка,
поэтому этот замер не используется для сравнения производительности. Время на
физическом Android-устройстве и реальные междугородние результаты до окончания
отдельного CI-job остаются непроверенными. Страновой artifact не удалось скачать
в эту среду: хранилище вернуло 403, а connector ограничивает загрузку 512 MiB
при размере пакета 1,21 GB.
